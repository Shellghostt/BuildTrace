## Scope and preserved contracts

Implement BT-014–BT-019: DSSE/PAE, local Ed25519/ECDSA P-256 signing, Sigstore keyless signing,
offline signed-statement verification, explicit signer/issuer policy and offline/tamper fixtures.
Reusable GitHub Action/release integration remains M5; SBOM, dependency discovery and reproducibility
remain M6. A focused live keyless CI test is M4 evidence, not delivery of the M5 reusable action.

Preserve M2 manifest v1, canonical file/directory/symlink hashing, mutation/path/output guards and
`verify --manifest` reason/exit/report semantics. Keep M3 `record --sign none` default bytes, relative
subject names, field meanings, deterministic IDs and unsigned `inspect` scope/bounds. Do not replace
those paths with a signature-only check or a new interpretation of the recorder's build type.

Signing authenticates the signer of these recorded observations/assertions and binds payload bytes.
It does not witness the original build, prove that a declared source produced the artifact, establish
dependency completeness, safety, reproducibility or a SLSA level. `builder.id` stays a self-declared
recorder label; certificate/OIDC identity or an externally trusted public key is the signer evidence.

## DSSE and output

Use payload type `application/vnd.in-toto+json`. Sign DSSE PAE over the exact payload bytes:
`DSSEv1 <byte-length(type)> <type> <byte-length(payload)> <payload>`.
Lengths are UTF-8 byte counts encoded as decimal ASCII. Verify the same bytes before interpretation;
never deserialize/reformat the payload and then verify different bytes. Preserve the M3 canonical
statement, including its defined LF and invocation-ID hash, inside the envelope.

Reject missing/ambiguous fields, duplicate JSON keys, malformed base64, unsupported payload types,
empty/invalid signature material and unsupported security formats explicitly. Retain the decoded
statement's 16 MiB/64-level/200,000-token/1,000-resource bounds. Proposed outer envelope/bundle limit is
32 MiB (base64 expands a 16-MiB payload), with at most 16 signatures and separate certificate/proof/
trust-material bounds. Final limits and signature-selection rules must be accepted and boundary-tested.

Choose keyless packaging under ADR 0006. The recommended single standard Sigstore bundle includes the
DSSE envelope and offline verification material in one atomically published file; local signing emits
a DSSE envelope. If choosing an envelope plus sidecar instead, specify failure/replacement semantics
that prevent mismatched or partial pairs. Signed output is not required to be byte-identical across
keyless certificates or randomized signatures; the unsigned payload remains deterministic.

Validate output destinations before capture/signing. Do not overwrite/include selected artifacts,
publish partial signed output, log private material, or silently emit unsigned output if signing fails.
`--sign none` stays an explicit supported path; requesting local/keyless signing must either succeed
in that mode or fail visibly.

## Local keys

Use explicit trusted public-key input/pinning outside the attestation. An embedded `keyid`, public key
or certificate supplied by an attacker is not a trust anchor. Define supported PEM formats, key IDs,
algorithm verification and malformed/wrong/unsupported key behavior. The PLAN permits Ed25519 and
ECDSA P-256 only; reject other algorithms without a downgrade.

The private-key path comes from `BUILDTRACE_SIGNING_KEY`; key bytes/passphrases never enter CLI
arguments, reports, attestations, stdout/stderr or subprocess environments. Bound file reads and
document file handling on Windows/POSIX. Local signing makes no OIDC/Fulcio/Rekor or network calls.
Local verification runs no git/OIDC/Fulcio/Rekor and needs no network. Test with disposable synthetic
keys, never live credentials.

## Keyless trust and authenticated signing time

Signing requires an explicitly chosen OIDC/Fulcio/transparency workflow and bounded network access.
Tokens and ephemeral private keys remain private. Pin maintained libraries, versions, checksums,
licenses and configured trust/service endpoints before adding dependencies. M3's standard-library-only
runtime does not silently authorize an unreviewed signing stack.

Offline verification requires locally available authenticated trust roots and certificate/log/time
evidence bound to this exact payload/signature. Verify chain/algorithm, required certificate extensions,
issuer and signer identity using trusted policy, not labels in the payload or arbitrary bundle URLs.
Use authenticated signing time to check short-lived certificate validity, so a valid historical
signature can verify after the leaf certificate expires. A caller timestamp, recorder build-time claim
or unsigned `integratedTime` is not trusted time evidence.

The old PLAN made Rekor optional and deferred inclusion proofs. That is unresolved for full offline
keyless verification. The proposal requires a standard offline bundle with authenticated log/time
evidence (such as a validated signed entry/timestamp and required inclusion proof/checkpoint), plus
pinned trusted keys/roots. If another time mechanism is chosen, document and test its cryptographic
binding. Missing evidence fails rather than prompting an implicit online lookup or trusting the clock
claimed by the attestation. Describe offline trust-root update/revocation limits accurately.

## Policy, artifact selection and results

- Keyless verification requires explicit expected certificate identity and OIDC issuer. Define exact
  matching/normalization; do not use substring matching, unanchored patterns or the payload's `builder.id`.
  A recorder-label constraint, if provided, is a separate assertion filter with separate semantics.
- Local mode requires a trusted public key. Resolve mode selection, policy flags, trust-root files and
  incompatible combinations before code. Missing required policy is invalid input, not trust-any-signer.
- Open only artifacts explicitly selected by the caller under a declared root/mapping. Require one
  matching unique canonical subject per selection; do not follow paths or links embedded in an attestation
  to fetch/open arbitrary files. Recompute each selected digest and, for the known recorder type, kind/
  byte count with M2 hashing. State the checked subject set and any unselected subjects in the report.
- Interpret only accepted known build types under their versioned contracts. M3 inspect may still show
  unknown types as uninterpreted. Optional expected source/dependency checks compare declared URI/commit
  claims with user policy; they do not prove original artifact source or require invented dependencies.
- Unsigned input is rejected by the signed verifier by default. If the planned `--allow-unsigned` mode
  ships, require explicit opt-in, an unsigned scope/warning and digest checks; it cannot satisfy signer/
  issuer policy or be reported as authenticated verification.
- Report checked scope, signer evidence/policy, selected artifact checks and stable reasons with one
  JSON document under `--json`. Retain exits 0 success, 1 verification mismatch, 2 invalid/unsupported
  input or usage, 3 tool/I/O failure. Settle precise reason/precedence mapping in ADR 0006.

Every PLAN 9.3 reason needs a test: `invalid_input`, `signature_invalid`, `identity_mismatch`,
`subject_missing`, `digest_mismatch`, `unsupported_build_type`, `dependency_mismatch`.
Also specify missing signature, untrusted/invalid certificate, missing/invalid signing-time or trust
material, artifact missing/unreadable, kind/size mismatch, output failure and ambiguous-signature cases.
Failure cannot produce an unsigned/signed success verdict or continue by skipping the failed check.

## Acceptance and future evidence

- [ ] DSSE PAE matches independent vectors, including byte lengths and payload LF; type/payload/base64/
  duplicate-key/signature bounds and reordered/tampered data have explicit tests.
- [ ] Local Ed25519 and ECDSA P-256 signing/verification succeed with externally pinned public keys and
  no network; wrong/malformed/unsupported keys and algorithms fail with stable reasons.
- [ ] Keyless signing in a real authorized GitHub Actions runner produces the selected standard bundle/
  envelope format with all required offline material; no signing failure silently downgrades to unsigned.
- [ ] Offline keyless verification succeeds after leaf expiry using authenticated signing time and pinned
  test roots; missing/forged time/proofs, wrong issuer/identity, invalid chain and untrusted roots fail.
- [ ] Tampered payload/signature/artifact, missing/duplicate subject, kind/size mismatch, unknown build type,
  optional dependency mismatch, policy/input/I/O failures each have reason and CLI exit tests.
- [ ] Verification executes no git/build/network command, fetches no bundle-supplied URL and opens only
  selected rooted artifacts; traversal/symlink/mapping and oversized/proof/parser inputs are bounded.
- [ ] Signed/authenticated, unsigned opt-in, inspected and unsigned-manifest results remain distinct;
  payload builder labels/caller assertions never become proof of signer identity or original build history.
- [ ] Synthetic private keys/tokens are absent from all output/errors/subprocess environments; interrupted
  signing and failed file writes leave no partial or mismatched published result.
- [ ] Existing M2/M3 bytes, goldens, parser/output guards, deterministic unsigned IDs, 1-GiB memory gate,
  race, offline container and pinned upstream format tests continue to pass.
- [ ] Independent DSSE/Sigstore verification of synthetic signed fixtures succeeds with documented version
  pins; format compatibility checks remain separate from signature/identity evidence.
- [ ] Final native Windows/Ubuntu/macOS CI, runtime/test-dependency audit and focused live keyless checks
  pass; dependencies and offline trust-root setup have reproducible instructions.
- [ ] The eventual M4 validation record maps each criterion to actual tests, commands, evidence and skips.

Use existing `make test`, `make race`, `make lint`, `make build`, `make schemas` after `make schema-setup`,
and `make memory-gate`; preserve the pinned/offline setup and working x64 GCC in
[M3 validation](../testing/m3-provenance.md). Windows Make still needs an explicit `VERSION` override
for its Unix version expression. New live signing tests require separate setup; offline cases must run
with network disabled after dependencies/trust fixtures are prepared. No signing or dependency changes
accompany this documentation pass.

## Handoff

First settle the standard bundle, trusted-time/root and exact signer-policy design, including new runtime
dependency pins. Add DSSE and negative trust fixtures before signers; preserve accepted ADRs 0001–0005.
The current request authorizes M4 implementation and local verification. Feature-branch publication/live CI and releases require their applicable user authorization.
