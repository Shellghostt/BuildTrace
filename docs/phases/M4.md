## Scope and preserved contracts

Implement BT-014–BT-019: DSSE/PAE, local Ed25519/ECDSA P-256 signing, Sigstore keyless signing,
offline signed-statement verification, explicit signer/issuer policy and offline/tamper fixtures.
Reusable GitHub Action/release integration remains M5; SBOM, dependency discovery and reproducibility
remain M6. A focused live keyless CI test is M4 evidence, not delivery of the M5 reusable action.

Preserve M2 manifest v1, canonical file/directory/symlink hashing, mutation/path/output guards and
`verify --manifest` reason/exit/report semantics. Keep M3 `record --sign none` default bytes, relative
subject names, field meanings, deterministic IDs and unsigned `inspect` scope/bounds. Do not replace
those paths with a signature-only check or a new interpretation of the recorder's build type.

Signing authenticates the signer of these recorded observations/assertions and binds payload bytes.
It does not witness the original build, prove that a declared source produced the artifact, establish
dependency completeness, safety, reproducibility or a SLSA level. `builder.id` stays a self-declared
recorder label; certificate/OIDC identity or an externally trusted public key is the signer evidence.

## DSSE and output

Use payload type `application/vnd.in-toto+json`. Sign DSSE PAE over the exact payload bytes:
`DSSEv1 <byte-length(type)> <type> <byte-length(payload)> <payload>`.
Lengths are UTF-8 byte counts encoded as decimal ASCII. Verify the same bytes before interpretation;
never deserialize/reformat the payload and then verify different bytes. Preserve the M3 canonical
statement, including its defined LF and invocation-ID hash, inside the envelope.

Reject missing/ambiguous fields, duplicate JSON keys, malformed base64, unsupported payload types,
empty/invalid signature material and unsupported security formats explicitly. Retain the decoded
statement's 16 MiB/64-level/200,000-token/1,000-resource bounds. Outer envelope/bundle limits are
32 MiB, 64 levels and 200,000 tokens. M4 authenticates exactly one signature against explicit policy;
2–16 signatures fail as `ambiguous_signatures`, and 17 or more exceed the parser bound. Signature bytes
are capped at 128. Separate certificate/proof/trust bounds and strict security-field/base64 validation
are accepted in ADR 0006 and covered by boundary/negative tests.

Local signing emits a DSSE envelope. Keyless signing emits one standard Sigstore v0.3 bundle
(`application/vnd.dev.sigstore.bundle.v0.3+json`) containing the DSSE envelope and offline material,
published atomically after validation. It contains one leaf certificate, one Rekor v1 `dsse/0.0.1`
entry, a SET, inclusion proof and signed checkpoint. Alternate bundle/log/timestamp formats fail
explicitly. Signed output need not be byte-identical across keyless certificates or randomized
signatures; the unsigned payload remains deterministic.

Validate output destinations before capture/signing. Do not overwrite/include selected artifacts,
publish partial signed output, log private material, or silently emit unsigned output if signing fails.
`--sign none` stays an explicit supported path; requesting local/keyless signing must either succeed
in that mode or fail visibly.

## Local keys

Use explicit trusted public-key input/pinning outside the attestation. An embedded `keyid`, public key
or certificate supplied by an attacker is not a trust anchor. Private keys use one unencrypted PKCS#8
Ed25519/P-256 or SEC1 P-256 PEM block; external public keys use one PKIX `PUBLIC KEY` block. Key IDs
are SPKI SHA-256 fingerprints and supply no trust by themselves. Reject other algorithms, encrypted
or ambiguous PEM and malformed/wrong keys with the accepted reasons, without a downgrade.

The private-key path comes from `BUILDTRACE_SIGNING_KEY`; key bytes/passphrases never enter CLI
arguments, reports, attestations, stdout/stderr or subprocess environments. Key reads are bounded to
16 KiB, check opened-file identity and reject terminal symlinks/nonregular files. POSIX requires
owner-only key permissions; Windows callers restrict the ACL. Local signing makes no OIDC/Fulcio/Rekor or network calls.
Local verification runs no git/OIDC/Fulcio/Rekor and needs no network. Test with disposable synthetic
keys, never live credentials.

## Keyless trust and authenticated signing time

Keyless signing uses bounded in-process OIDC, public-good Fulcio v2 and Rekor v1 requests with a P-256
ephemeral key, finite response/time limits and a two-minute cancellation deadline. Tokens come from a
bounded private `BUILDTRACE_OIDC_TOKEN_FILE` or GitHub Actions OIDC with audience `sigstore`; no browser
login, token subprocess or bundle-selected endpoint is used. Tokens and ephemeral keys remain private.
The final Go 1.26.11-compatible stack is pinned in go.mod/go.sum and ADRs 0006–0008, including
Sigstore-Go v1.3.0, Rekor v1.5.4, Sigstore v1.10.11 and protobuf-specs v0.5.2. The
[dependency/license inventory](../dependencies/m4-signing.json) records imported modules and checksums.

Offline verification requires locally available authenticated trust roots and certificate/log/time
evidence bound to this exact payload/signature. Verify chain/algorithm, required certificate extensions,
issuer and signer identity using trusted policy, not labels in the payload or arbitrary bundle URLs.
Use authenticated signing time to check short-lived certificate validity, so a valid historical
signature can verify after the leaf certificate expires. A caller timestamp, recorder build-time claim
or unsigned `integratedTime` is not trusted time evidence.

ADR 0006 requires SET-authenticated integrated time bound to the exact entry/payload/signature/leaf,
trusted certificate/CT validation, Merkle inclusion and signed checkpoint verification. Trust comes from
an externally provisioned standard trusted-root v0.1 snapshot, bounded to 1 MiB. Missing or invalid
evidence fails without an online lookup. Separate authenticated TUF setup can provision a snapshot;
offline verification cannot discover later compromise/revocation or prove global log consistency.

## Policy, artifact selection and results

- Keyless verification requires explicit `--expect-identity` and `--expect-issuer`. Match literal bounded
  UTF-8 strings without trimming, normalization or regex; do not use the payload's `builder.id`.
  A recorder-label constraint, if provided, is a separate assertion filter with separate semantics.
- Local verification requires `--public-key`; keyless verification requires `--trusted-root` plus exact
  identity/issuer. These modes cannot be combined. Missing required policy is invalid input.
- Open only artifacts explicitly selected by the caller under a declared root/mapping. Require one
  matching unique canonical subject per selection; do not follow paths or links embedded in an attestation
  to fetch/open arbitrary files. Recompute each selected digest and, for the known recorder type, kind/
  byte count with M2 hashing. State the checked subject set and any unselected subjects in the report.
- Interpret only accepted known build types under their versioned contracts. M3 inspect may still show
  unknown types as uninterpreted. Optional expected source/dependency checks compare declared URI/commit
  claims with user policy; they do not prove original artifact source or require invented dependencies.
- Unsigned input is rejected by the signed verifier by default. `--allow-unsigned` requires explicit
  opt-in, an unsigned scope/warning and digest checks; it cannot satisfy signer/
  issuer policy or be reported as authenticated verification.
- Report checked scope, signer evidence/policy, selected artifact checks and stable reasons with one
  JSON document under `--json`. Retain exits 0 success, 1 verification mismatch, 2 invalid/unsupported
  input or usage, 3 tool/I/O failure. ADR 0006 defines precise reasons, precedence and mapping.

Every PLAN 9.3 reason needs a test: `invalid_input`, `signature_invalid`, `identity_mismatch`,
`subject_missing`, `digest_mismatch`, `unsupported_build_type`, `dependency_mismatch`.
Additional accepted reasons cover missing signature, untrusted/invalid certificate, missing/invalid
signing-time or trust material, artifact missing/unreadable, kind/size mismatch, output failure and
ambiguous-signature cases; the validation record maps these to targeted tests.
Failure cannot produce an unsigned/signed success verdict or continue by skipping the failed check.
